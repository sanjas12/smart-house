# Automation Hub — архитектура

## Текущее состояние (2026-10-21)

Реализованы FastAPI-сервер с SQLite через `sqlite3` и демонстрационный
Python-сборщик с GUI на PyQt5 (настройки, запуск/остановка, показания и журнал)
и консольным режимом `--cli`. Сетевой обмен GUI выполняется в отдельном потоке. Таблицы создаются при импорте `server/app/main.py`.
Мобильный клиент ещё не создан. Инструкции установки и запуска — в [Readme.md](Readme.md).

Работающие эндпоинты:

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/telemetry` | Сохранить показание |
| GET | `/api/devices` | Устройства с сохранённой телеметрией |
| GET | `/api/devices/{device_id}/history` | История, новые сверху; limit 1–500, offset ≥ 0 |
| GET | `/api/devices/{device_id}/latest` | Получить последнее показание |
| POST | `/api/devices/{device_id}/command` | Поставить команду в очередь |
| GET | `/api/devices/{device_id}/commands` | Получить команды со статусом pending |
| POST | `/api/commands/{command_id}/ack` | Перевести команду из pending в done |

Сборщик генерирует случайные показания, получает команды и подтверждает их
без реального выполнения. История и список устройств доступны через API и вкладку GUI. ORM, миграции,
аутентификация и протоколы устройств — планы, а не готовые возможности.
Прямые зависимости закреплены под Python 3.8; запуск на Windows 7 требует
отдельной проверки. Python 3.8 больше не получает обновлений безопасности.

Ниже — проектный план. Предлагаемые API, библиотеки и структура могут отличаться
от реализации; актуальная структура приведена в README.


**Потоки данных:**

1. **Сбор:** Десктопное приложение опрашивает устройства и отправляет телеметрию на сервер (`POST /api/telemetry`).
2. **Хранение:** Сервер сохраняет данные в БД.
3. **Отображение:** Мобильное приложение запрашивает данные (`GET /api/devices/{id}/latest`).
4. **Управление:** Мобильное приложение отправляет команду (`POST /api/devices/{id}/command`), сервер ставит её в очередь для десктопа или передаёт устройству.

## 3. Компоненты системы

### 3.1. Десктопное приложение — «Сборщик данных»

| Параметр | Значение |
|---|---|
| Язык | Python 3.8.10 (целевая версия для Windows 7) |
| Роль | Опрос устройств, нормализация данных, отправка на сервер |
| Протоколы устройств | Modbus TCP/RTU, MQTT, HTTP (по мере изучения) |
| Библиотеки | `pymodbus`, `paho-mqtt`, `requests` |
| Конфигурация | YAML/JSON-файл со списком устройств и их адресов |

**Задачи для изучения:**
- Работа с асинхронностью (`asyncio`) или потоками для параллельного опроса.
- Парсинг конфигурации.
- Обработка ошибок связи с устройствами (таймауты, ретраи).
- Логирование.

### 3.2. Сервер — «Мозг и хранилище»

| Параметр | Значение |
|---|---|
| Язык | Python 3.8.10 (целевая версия для Windows 7) |
| Фреймворк | FastAPI |
| Роль | REST API, хранение истории, очередь команд |
| БД (старт) | SQLite |
| БД (развитие) | PostgreSQL |
| Аутентификация (опционально) | JWT-токены |

**Основные эндпоинты (черновик):**

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/telemetry` | Приём телеметрии от десктопа |
| `GET` | `/api/devices` | Список устройств |
| `GET` | `/api/devices/{id}/latest` | Последние значения устройства |
| `GET` | `/api/devices/{id}/history` | История значений (с параметрами `from`, `to`) |
| `POST` | `/api/devices/{id}/command` | Отправка команды устройству |
| `GET` | `/api/devices/{id}/commands` | Получение очереди команд (для десктопа) |

**Задачи для изучения:**
- Проектирование REST API.
- Валидация входных данных (Pydantic).
- Работа с ORM (SQLAlchemy) и миграциями (Alembic).
- Асинхронные эндпоинты.

### 3.3. Мобильное приложение — «Пульт управления»

| Параметр | Значение |
|---|---|
| Платформа | HarmonyOS (Huawei) |
| Язык | **ArkTS** (обязательно, не Python) |
| IDE | DevEco Studio |
| UI-фреймворк | ArkUI (декларативный) |
| Сетевой модуль | `@ohos.net.http` / `@kit.NetworkKit` |

**Важные нюансы:**
- В `module.json5` добавить разрешение `ohos.permission.INTERNET`.
- Для отладки по HTTP (не HTTPS) в `network_config.json` установить `cleartext-traffic-permitted: true`.
- Python на телефоне **не используется** — вся клиентская логика на ArkTS.

**Задачи для изучения:**
- Основы декларативного UI (ArkUI).
- Управление состоянием (`@State`, `@Prop`).
- HTTP-запросы и парсинг JSON.
- Построение простых графиков (можно начать с текстового вывода, позже — библиотеки чартов).

## 4. Порядок разработки (roadmap для обучения)

1. **Сервер (MVP):** FastAPI + SQLite + 2 эндпоинта (`POST /telemetry`, `GET /latest`). Проверка через `curl`/Postman.
2. **Десктоп (MVP):** Python-скрипт, отправляющий фейковые данные на сервер. Убедиться, что данные сохраняются.
3. **Мобильное приложение (MVP):** Проект в DevEco Studio, один экран, `GET /latest`, вывод JSON в текст.
4. **Интеграция:** Заменить фейковые данные на реальный опрос одного устройства (Modbus/MQTT).
5. **Управление:** Добавить очередь команд на сервере и обработку на десктопе.
6. **Развитие:** Графики, история, аутентификация, несколько устройств, PostgreSQL.

## 5. Принятые технические решения и их обоснование

| Решение | Обоснование |
|---|---|
| Python на десктопе и сервере | Быстрая разработка, богатая экосистема библиотек для протоколов автоматизации |
| FastAPI для сервера | Асинхронность «из коробки», автоматическая документация (Swagger), Pydantic для валидации |
| ArkTS для Huawei | Единственный официально поддерживаемый язык для «чистой» HarmonyOS; Android-стек (Java/Kotlin) не подходит |
| SQLite на старте | Не требует установки сервера БД, идеально для учебного проекта |
| HTTP/REST между компонентами | Простота отладки, повсеместная поддержка, легко расширяется до WebSocket |

## 6. Ограничения и известные подводные камни

- **Python не запускается на телефоне Huawei** — не пытаться обойти это костылями.
- **Cleartext HTTP** в HarmonyOS по умолчанию может блокироваться — требуется явное разрешение в конфиге.
- **Разные протоколы устройств** (Modbus, MQTT, Zigbee) — начинать с одного, расширять по мере изучения.
- **Безопасность** в учебном проекте не приоритет, но стоит помнить: без аутентификации сервер открыт всем в локальной сети.
